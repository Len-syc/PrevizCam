# 镜头审查

读取最新草案 ID/version/baseRevision。先 check_draft 获取结构与几何提示，再 render_frames。省略 `frames` 时它会自动覆盖每个必看时刻（首、中、尾加相机与走位关键点）并按整镜装批，返回的 `coverage` 列出每镜还缺哪些 `t`；首轮默认只回传一张接触表，需要细节时用 `view: "frames"` 或指定 `frames` 取单帧。工具名称与参数可从 `previzcam://reference/previs-contract` 获取。

逐镜覆盖首、中、尾与关键点，再对问题时刻补帧。关注人物头部、视线、建筑遮挡、相机轨迹、固定摄影约束和镜间轴线/位置接续。记录每项问题的镜头 ID、镜内时间、实际证据、影响和可行修正。图像输出带版本与保存路径，可用于后续复核。`submit_draft` 会拒绝仍有必看时刻未渲染的草案，并逐个列出 `镜头 X 缺 t=…`。

区分三类结论：程序报告、实际画面观察、尚未验证。每镜最多 301 个采样时刻不是连续碰撞保证；当前不检查人物相互遮挡、肢体碰撞、对白时长、真实景深和精细表演。

用户要求修正时，先修影响叙事或明显不可用的问题，更新完整 plan，重新检查并重取受影响画面。默认最多三轮；保留仍未解决的事项供用户审阅。不要通过移除剧本必要人物来消除检查提示。

若宿主无法查看图像，明确仅完成了数据/几何检查，视觉审查留作待办。未查看的镜头不能写成“已审核”。只读审查请求不应自动改草案或提交正式项目。
